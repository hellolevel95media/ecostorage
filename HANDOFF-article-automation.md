## Design (decided, no schema change needed)
1. **Queue = drafts with a future `published_at`.** The `articles` table only allows `status` of `draft` or `published`, and RLS already hides drafts from the public. A scheduled article is a `draft` row whose `published_at` is the intended publish date.
2. **Daily Vercel cron** `GET /api/cron/publish-articles`, copying the pattern in `src/app/api/cron/affiliate-relay/route.ts` (Bearer `CRON_SECRET`, `timingSafeEqual`, admin client from `src/lib/supabase/admin.ts`). Each run: find the oldest `draft` with `published_at <= now()`, set `status='published'` and `published_at=now()`, then `revalidatePath` for `/resources`, `/resources/<slug>`, `/`, `/personal`, `/sitemap.xml`. Publish **one** per run (cap), even if several are overdue, so a missed day never dumps a backlog. Return `{published: slug|null}`.
3. Add to `vercel.json` next to the existing cron, e.g. `{ "path": "/api/cron/publish-articles", "schedule": "0 1 * * *" }` (09:00 Singapore). Keep `"regions": ["sin1"]`. Vercel Hobby allows daily crons and 2 per project; confirm the plan if a third is ever added.
4. Because pages are cached for 60 seconds with `generateStaticParams`, new slugs render on first visit and then cache. The revalidate calls make the listing and sitemap update immediately.

## Risks and gotchas
- **Admin edits to a scheduled draft:** `ArticleForm` sets `published_at` to the existing value only when status is `published`; saving a scheduled **draft** from `/admin` writes `published_at = null`, which silently removes it from the queue. Either tell the owner not to open queued drafts, or change the form to keep `published_at` for drafts (small edit in `src/components/admin/ArticleForm.tsx`, line ~58).
- **Existing drafts** (`what-to-expect-on-moving-day`, `corporate-storage-singapore-businesses`) have `published_at = null`, so the cron ignores them. Leave them for the owner.
- **Duplicate topics:** these overlap partly with live pieces (quote article, `store-furniture-during-hip`). The queue articles take different angles; do not merge or delete live ones.
- **Facts to have the owner review before publishing** (written from general knowledge and `PRODUCT.md`, not verified operations): crate vs pallet wording (09), the "small share of space is climate-controlled" mention (09, 10), packing help for fragile items "extras communicated in advance" (15), and the list of items a provider typically does not accept (14: perishables, flammables, hazardous; confirm EcoStorage's actual terms). Nothing here should be presented as legal or tenancy advice (06, 16 say to check agreements and ask an accountant).
- **Quality over volume:** auto-published AI-assisted content is fine for search only if it is genuinely useful and accurate. The owner should skim each title list and may drop weak ones.
- **No Mandarin versions yet.** The live Mandarin articles are machine translations awaiting native review; do not add more until that is sorted.

## Maintenance (the "periodic" part)
- Every 1 to 2 months: check `/admin` or Supabase for remaining queued drafts (`select slug, published_at from articles where status='draft' and published_at > now() order by published_at`). When fewer than ~7 remain, ask for a new batch; use Search Console and the GA4 dashboard in `/admin` to pick topics that match what people actually search.
- Reuse the same flow for a new batch: drop new `NN-slug.md` files in `content/articles/queue/`, run the seed script with a new start date.
- If a day fails, the next day's run publishes the oldest overdue one, so nothing is skipped. If the cron returns 401, `CRON_SECRET` is missing or changed.
